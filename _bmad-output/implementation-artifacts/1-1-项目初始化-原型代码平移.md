## Dev Notes

### 本 Story 的本质
这是 **Story 0 类基础工作**：搭脚手架 + 把原型里已验证的「资产」搬进 `web/`，同时**剔除**只为原型 PWA spike 服务的「负债」。**没有业务功能**——产出是一个能 `npm run dev`、`lint` 干净、`tsc` 通过、且无 mock/IndexedDB/Serwist 残留的干净基线。后续所有 Story 都长在它上面。

### ⛔ 强制护栏（architecture「All AI Agents MUST」节，违反 = 返工）
1. **平移即净化**：搬运时**保留**类型 / 纯函数 / iframe pattern；**剔除** IndexedDB / Service Worker / mock 数据。**不要"先放着等以后删"**。[Source: architecture/implementation-patterns-consistency-rules.md#enforcement-guidelines #9]
2. **PRD §3 Glossary 术语强制**：代码 / 注释 / 文件名沿用 Entry / 归档(archive) / 时间线(Timeline) / 完整渲染(FullRender)，**禁同义词**。
3. **命名约定**：组件文件 `PascalCase.tsx`；非组件 TS 文件 `kebab-case.ts`；类型/接口 `PascalCase`；函数 `camelCase` 动词开头；常量 `SCREAMING_SNAKE_CASE`。[Source: architecture/implementation-patterns-consistency-rules.md#naming-patterns]
4. **`--no-src-dir`**：根级平铺 `app/` / `components/` / `lib/`（与原型一致，便于平移），**勿**生成 `src/`。
5. 本 Story **不**接入 DB / Auth / R2 / DESIGN.md tokens（分别属于 Story 1.2 / 1.3 / Epic 2 / Story 1.4）——空壳就是空壳，**不要**提前实现。

### 平移的纯函数（已读原型源码确认，行为须逐字保留）
- `sortEntries<T extends { archivedAt: string }>(entries, 'desc'|'asc')` → 拷贝排序，desc=最新在前。
- `groupByMonth<T extends { archivedAt: string }>(entries)` → 按 `YYYY-MM` 分组，`label` = `"{年} 年 {月} 月"`（`parseInt` 去前导零）。
- `relativeTime(iso)` → 档位：刚刚 / N 分钟前 / N 小时前 / N 天前 / N 周前 / N 个月前 / N 年前。
- `absoluteTime(iso)` → `"{年} 年 {月} 月 {日} 日"`。
- `getAdjacentEntries<T extends { id; archivedAt }>(entries, id, direction)` → 先 `sortEntries` 再取相邻 `{ prev?, next? }`。
- ⚠️ `findEntryById` 原型存在但 V1 真实查找走 DB（`lib/db/queries.ts#getEntryById`，Story 2.3 建）。可将 `findEntryById` 并入 `get-adjacent.ts` 作内部 helper，或省略——**不要**新建 `find-entry.ts` 文件（非 epic 要求）。
- ⚠️ `extract-title.ts` **新建**：`extractTitle(htmlContent, filename)` —— 正则/DOMless 抽 `<title>...</title>` 文本，trim 后为空则 fallback `filename` 去掉 `.html`/`.htm` 扩展名。保持纯函数（无 DOM API，服务端/客户端均可调）。

### archivedAt 类型决策（重要，影响 Story 1.2 衔接）
原型纯函数签名约束 `archivedAt: string`（ISO）。架构数据格式约定：「日期/时间 ISO 8601 字符串；TS 内运行时用 `Date`，序列化时回字符串」，而 Drizzle `timestamptz`（Story 1.2）查询默认返回 `Date`。
- **本 Story 取向**：`Entry.archivedAt` 与 `createdAt` 定义为 `string`（ISO），使平移的纯函数**零改动**即可工作（满足「行为不变」）。
- **衔接说明（写给 Story 1.2 dev）**：`lib/db/queries.ts` 在 DB 边界把 `Date` 序列化为 ISO `string` 再返回 `Entry`，保持纯函数与组件契约稳定。此项记入下方 Dev Agent Record / 也是给后续 Story 的明确交接，**本 Story 不需实现 DB 层**。

#### Med（正确性风险 / 约定违反）

**[M1] `extractTitle` HTML 实体未解码**
- **文件：** `web/lib/entry/extract-title.ts:9`
- **原因：** 正则抽取 `<title>` 内容后仅做 whitespace normalize（`replace(/\s+/g, " ").trim()`），未解码 HTML 实体。当 HTML 文档标题包含实体编码（如 `<title>MindPrint &amp; 笔记</title>`），函数返回原始 `"MindPrint &amp; 笔记"` 而非解码后的 `"MindPrint & 笔记"`。此问题在 Story 2.2 归档链路上线后直接影响用户可见标题。
- **建议修法：** 在 `trim()` 后加轻量实体解码：
  ```ts
  const decoded = title
    .replace(/&amp;/g, '&')
    .replace(/&lt;/g, '<')
    .replace(/&gt;/g, '>')
    .replace(/&quot;/g, '"')
    .replace(/&#(\d+);/g, (_, n) => String.fromCharCode(Number(n)))
    .replace(/&#x([0-9a-f]+);/gi, (_, h) => String.fromCharCode(parseInt(h, 16)));
  ```
  或在 Story 2.2 调用点（Server Component 或 Server Action）对返回值做解码。

**[M2] `SortToggle` props 契约与 Story 3.3 URL state 重构方向不对齐**
- **文件：** `web/components/SortToggle.tsx:6-8`
- **原因：** 当前 props `{ value: SortDirection; onChange: (next: SortDirection) => void }` 是状态回调模式，适合父组件持有 `useState`。但 Story 3.3 要将排序改为 URL search param `?sort=asc|desc` 驱动，届时不需要 `value`/`onChange`，组件应读 `useSearchParams()` + 调 `router.replace()`。现在的签名与未来 API 存在根本性差异，Story 3.3 需整体替换。
- **建议：** 在组件注释中明确标注"此 prop 签名为临时占位，Story 3.3 整体替换为 URL state 驱动"，避免后续开发者误依赖。
