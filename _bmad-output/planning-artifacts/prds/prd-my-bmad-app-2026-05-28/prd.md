## 1. 愿景

MindPrint 是 **alex 自托管的个人 HTML 思维档案库**——把日常借助 AI 产出的、散落在 ~/Downloads 和各工作项目目录里的 .html 思维产物（UI 规范、调研报告、原型、思考片段）收拢到一个**可时间线浏览、可一键完整渲染**的私人 web 应用里。

对 alex 来说，"回看自己旧产物"已经是一个能切实"提升思维逻辑"的日常行为，但这个行为正被"文件散落、记不起来、Finder 双击 .html 体验破碎"持续侵蚀，且**已经发生过实际丢失**。MindPrint 让这件已经在做、但难以维持的事变得可持续。它同时承担一个非常具体的目标：成为 alex 借助 AI 从前端向全栈转型的**第一个真实项目**——既是工具，也是历练。

五年视角下，MindPrint 沉淀的不仅是 .html 文件，**更是** alex 多年思维形态的可回溯档案。这是这个项目最初设立的初心，也是它本质上无需"商业差异化"也值得存在的原因。

## 2. 目标用户

### 2.1 Jobs To Be Done

**alex** 作为 MindPrint 的唯一用户，使用本产品完成以下"待办"：

**功能性（functional）**：
- 把散落在 ~/Downloads 和工作目录的 .html 思维产物，**集中**到一个统一位置
- 按时间线**找回**曾经的某一份 Entry
- 在浏览器里以**原貌完整渲染**任何一份归档过的 .html——不再受 Finder 预览 / Notion 嵌入 / 临时分享服务的体验限制

**情绪性（emotional）**：
- 消除"我做过但找不到了"的焦虑——已经发生过的实际丢失不再重演

**认知性（cognitive）**：
- 通过周期性翻看时间线，把"我的思维在变化"从模糊感觉变成**可观察的事实**

**元层 / Builder 视角**：
- 把这个产品作为前→全栈能力闭环的**实战载体**，借此跑完一次 BMAD 全流程 *(此条不驱动 §4 任何 FR——它仅承接到 §8.2 元层 SMs SM-4/-5/-6)*

### 2.2 关键用户旅程（User Journeys）

> *Hobby / 单用户项目，UJ 走简化版——每条单句承载关键场景，足以约束下文 §4 的 FRs，不展开多幕剧。*

- **UJ-1. 找回一份旧 Entry**：alex 想回看某份特定的旧 .html（比如"那个两个月前的 AI 工具调研单页"）——打开 MindPrint，按时间倒序在时间线上翻找定位条目，点击进入完整渲染，找到内容。
- **UJ-2. 归档一份新 Entry**：alex 在 Cursor / Claude 让 AI 生成了一个新的 .html，从 ~/Downloads 拖入或选择上传到 MindPrint，系统自动捕获时间戳与基础元数据 [ASSUMPTION A1: 含从 `<title>` 抽取标题作为 Entry 显示名]，alex 确认后归档完成。
- **UJ-3. 思维演进回看**：alex 想"看看我这半年思维怎么变的"——从最早一条往后顺序浏览时间线，每条点开扫一眼，约 10 分钟扫完最近 30 条。

### 2.3 非用户（v1 不服务）

- 任何 alex 之外的人（包括朋友 / 同事 / 未来雇主——v1 不提供分享外链）
- 团队 / 协作场景
- 手机原生 App 用户（v1 浏览器响应式，无原生客户端）

## 3. 术语表（Glossary）

> *FRs / UJs / SMs **必须严格使用本表术语**，下游 UX / 架构 / Epic 阶段同。出现新术语时同步回填本表，禁止任何同义词。*

- **MindPrint** — 本产品的工作名称（**待最终确认**）。指代 alex 的个人 HTML 思维档案库整体。
- **alex** — 本产品**唯一用户**。
- **Entry（产物）** — 一份被归档进 MindPrint 的 .html 文件。**最小单元**：一份 .html ↔ 一个 Entry。每个 Entry 含 *原始 HTML 内容 + 元数据*。
- **元数据（Entry Metadata）** — 与一个 Entry 关联的非内容属性：归档时间、显示标题、原始文件名、文件大小等。
- **归档（Archive）** — 把一份 .html 从外部（如 ~/Downloads）纳入 MindPrint 管理的动作。`Archive` 后该 Entry 出现在时间线上。
- **时间线（Timeline）** — 所有 Entry **按归档时间倒序**排列的浏览视图。是 MindPrint 的主屏。
- **完整渲染（Full Render）** — 在浏览器内以原貌呈现一个 Entry 的 HTML（与双击 .html 在浏览器打开的视觉结果等价），但发生在 MindPrint 应用内、且**沙箱化**。

## 4. 功能特性（Features）

> *FR 全局编号。每个 FR 含"测试性后果（Consequences）"——意为 *可被测试 / 可被验收* 的具体行为约束，不是实现细节。*

### 4.1 归档（Archive）

**描述**：alex 通过把外部 .html 文件**纳入 MindPrint 管理**这一动作产生 Entry。归档动作包含三个连贯环节——**上传 → 元数据捕获与确认 → 进入档案库**。归档完成后 alex 立刻进入新 Entry 的完整渲染视图，看到"这个文件已经被档案库正确接住"。Realizes **UJ-2**。

**功能性需求**：

#### FR-1：上传 .html 文件

alex 可通过 **拖拽** 或 **点击选择** 把**单个** `.html` / `.htm` 文件上传到 MindPrint。Realizes UJ-2。

**测试性后果**：
- 接受扩展名 `.html` 与 `.htm`；其他扩展名一律拒绝并向 alex 返回明确提示
- 单文件大小上限 **10MB** [ASSUMPTION A2: 给 inline base64 图片 / 内嵌字体留余地]；超限拒绝并提示
- V1 仅接受单文件——多选 / 拖入多个文件触发明确"V1 仅支持单文件"提示
- 上传过程中网络中断 / 后端存储失败 → 提示用户并允许直接重试
- 失败不残留半个 Entry——任一环节失败时档案库状态不被污染（事务性）

**Out of Scope**：
- 批量上传 *(V1 不做)*
- 内容去重 *(V1 不识别重复)*。`[NOTE FOR PM]`：若使用过程中发现重复上传频繁发生，v2 可考虑加 hash 去重

#### FR-2：自动捕获元数据 + 可编辑显示标题

系统在上传时自动捕获 Entry 元数据，alex 可在归档落定前**预览**并**编辑显示标题**。Realizes UJ-2。

**测试性后果**：
- **自动捕获且不可编辑**：归档时间戳（=服务器接收文件的时刻，UTC）、原始文件名、文件字节大小
- **自动捕获 + alex 可编辑**：显示标题。抽取规则 [ASSUMPTION A1]——从 HTML 文档 `<title>` 标签内文本抽取为建议值；若无 `<title>` 或抽取结果为空白，fallback 为原始文件名（去扩展名）
- alex 在归档前看到预览界面，含一个**预填**的标题编辑框；alex 可修改或保留默认
- 显示标题最长 **200 字符** [ASSUMPTION A3]，超出截断并给提示
- alex 点击"确认"完成归档；点击"取消"丢弃此次上传，档案库不变
- 归档时间戳一旦写入即不可修改——这保证时间线的真实性

#### FR-3：归档成功后进入完整渲染

归档成功后系统自动把 alex 带到新 Entry 的完整渲染视图。Realizes UJ-2 → UJ-1 的衔接。

**测试性后果**：
- 归档成功后，alex 在 ≤ 1 次跳转内看到这份 Entry 的完整渲染（详见 §4.3）
- 新 Entry **立即**出现在时间线顶部（详见 §4.2）；alex 刷新或返回时间线时能看到
- 即使渲染本身失败（HTML 损坏 / 渲染异常），归档动作仍视为成功——Entry 已入库，alex 可从时间线后续手动诊断
- 提供清晰的"返回时间线"导航

**Notes**：
- *(§4.1 范围内未解决的开放问题已统一收入 §9 Open Questions)*

### 4.2 时间线浏览（Timeline）

**描述**：时间线是 MindPrint 的主屏——alex 每次进入应用首先看到的视图。承载两类核心动作：**找回某份特定 Entry**（UJ-1）与**顺序回看思维演进**（UJ-3）。**呈现形态为卡片网格**——每张卡片是一个 Entry 的视觉单位，含原 HTML 的**内容缩略预览**，让"思维形态"在浏览时直接可见，而不是被压缩成一行文字。

承接 brief §问题 中 "**画廊式翻看**" 体感隐喻——把每份 .html 当成视觉作品逐一翻阅，可漫游、可驻足、可翻页。**时间线不仅是找回工具，也是 alex 感受思维演进的视觉载体**——承接 §1 愿景中"看到自己思维变化"的产品初心（brief 反复强调的核心动机：通过回看自己旧产物提升思维逻辑）。

> *§1 thesis 边界说明*：HTML 内容缩略预览是该 thesis 的强解释——若 alex 体验中觉得缩略预览未带来质变，M3 retro 应考虑降级到首屏文本摘要（详见 OQ-8）。

Realizes **UJ-1, UJ-3**。

**功能性需求**：

#### FR-4：时间线卡片网格主屏

时间线以**卡片网格**形式展示所有 Entry，alex 可在倒序与正序之间切换排序，单击任一张卡片进入完整渲染。Realizes UJ-1, UJ-3。

**测试性后果**：
- **卡片网格**：响应式多列布局，宽屏多列、窄屏少列。每张卡片承载一个 Entry。
- **卡片内容**：每张卡片含三类信息——
  - **显示标题**（主，多行截断）
  - **HTML 内容缩略预览**（卡片视觉主体，呈现原 HTML 的视觉外观）[ASSUMPTION A5]。**可验收条件**——
    - (a) 缩略预览必须呈现原 HTML 的**颜色 / 字体 / 整体布局**（非纯文本退化）
    - (b) 不同 HTML 的缩略预览**必须可视化区分**（即看到缩略图能猜对是哪份）
    - (c) 生成失败时 fallback 到 "**显示标题 + 归档时间**" 占位卡片，**不得静默降级到纯文本摘要**——若架构阶段评估倾向方案变更（如方案 a 性能不足、需降级到方案 c 文本摘要），**必须触发 PM 回顾**（详见 OQ-8）
  - **归档时间**（次，相对格式如"3 天前"，hover 显示绝对时间戳）
- **缩略预览的沙箱化**：缩略预览同 §4.3 Full Render 共享 NFR-1 沙箱化约束——预览态也不得访问 MindPrint 的认证凭据 / 同源数据
- **默认排序**：归档时间**倒序**（最新归档在顶）
- **排序切换**：alex 可在"最新在前 / 最早在前"之间切换。V1 不持久化偏好——每次进入回到默认。`[NOTE FOR PM]`：若 alex 在使用中频繁切换到正序，v2 应持久化最近一次选择
- **单击打开**：单击任一卡片 → 跳转该 Entry 的 Full Render（详见 §4.3）
- **月份分隔**：按归档时间所在月份插入视觉分隔条（如"2026 年 5 月"），**无折叠交互**。**语义角色**——月份分隔不仅是视觉分组，也是 alex 感受"思维演进"的锚点（"我在 2026 年 3 月做了什么 / 2026 年 5 月做了什么"的对比感）
- **空状态**：档案库为空时显示明确引导（"还没有归档任何 .html，从这里开始"），含直达上传的入口
- **全量加载**：V1 一次性加载所有 Entry 的元数据，不分页 / 不懒加载 [ASSUMPTION A4: 5 年 N 百条 Entry 的元数据规模浏览器单次加载内无性能问题]。**缩略预览**可视情况懒加载（视口外延迟渲染），不算违反此条

**Out of Scope**：
- 标签 / 搜索 / 过滤 *(brief 明示，§7.2 重复)*
- 列表视图切换 *(V1 仅卡片网格，统一一种视觉范式)*
- 卡片 hover 预览 / 右键菜单 / 长按操作 *(交互模式单一——单击即进 Full Render)*
- 分页 / Entry 元数据懒加载 *(M3 阶段视实际条目数再评估)*
- 行内删除 / 编辑标题等"事后管理"动作 *(归 §4.4 私有访问与管理)*

### 4.3 完整渲染（Full Render）

**描述**：完整渲染是 MindPrint 兑现核心承诺——"以原貌看回旧产物"——的环节。alex 从时间线单击卡片，或归档成功后自动进入。HTML 在沙箱化容器中呈现，**视觉上等同于"双击 .html 在浏览器打开"**，但发生在 MindPrint 应用内、且封堵安全风险（详见 §5 NFR-1）。同时为 UJ-3 顺序回看提供"上一条 / 下一条"导航。Realizes **UJ-1, UJ-2（衔接）, UJ-3**。

**功能性需求**：

#### FR-5：完整渲染单一 Entry

alex 从时间线单击卡片或归档成功后自动跳转，进入该 Entry 的完整渲染视图。HTML 在沙箱化容器中以原貌呈现。Realizes UJ-1, UJ-2 → 衔接, UJ-3。

**测试性后果**：
- **渲染区域**：渲染视图占据应用主区域（全屏式），最大化原貌呈现
- **原貌等同性**：渲染结果**视觉上等同于**双击 .html 在浏览器打开。**仅一类例外**——沙箱化必要副作用（详见 §5 NFR-1）：例如 HTML 中的 `<script>` 尝试修改 `top.location` / 访问 `document.cookie` / 调用 `parent.postMessage` 等行为被沙箱阻止。**沙箱必要副作用的通用边界**：任何依赖宿主同源数据（cookie / `localStorage` / `sessionStorage` / IndexedDB）/ 第三方 SDK 注入 / 跨 origin 通信的渲染行为，若被沙箱阻断导致视觉退化，均视为"必要副作用"。外链资源加载失败导致的视觉退化参见 OQ-4
- **上下文 chrome**：渲染视图顶部展示——**显示标题**（主）+ **归档时间**（绝对时间戳）+ **"返回时间线"导航**
- **顺序导航**：提供 **"上一条 / 下一条 Entry"** 导航；方向跟随时间线当前的排序方向。Realizes UJ-3 的顺序回看体感
- **加载失败处理**：HTML 加载或渲染失败时显示明确错误信息，并保留"返回时间线"出口。**Entry 仍在档案库中**——渲染失败不影响归档状态（与 FR-3 一致）
- **响应式**：移动端浏览器同样能完整渲染（V1 硬约束："alex 在任意设备的浏览器都能访问"）
- **沙箱化约束**：渲染容器**必须无法**访问 MindPrint 应用的认证凭据 / 同源存储 / 应用 API。机制（iframe `sandbox` / 独立子域名 / CSP 等）留架构阶段决定——见 §5 NFR-1 与 `addendum.md` §2.1

**Out of Scope**：
- **沉浸全屏模式**（隐藏 MindPrint chrome，纯 HTML 占满屏幕）—— `[NOTE FOR PM]` v2 可加，alex 在使用中若反复想"专心看一份 Entry"时再评估
- **Entry HTML 内容编辑**——已归档 Entry 的 HTML 内容视为不可变快照；想"改一改"需要重新归档新版本（V1 不做版本对比，brief §V1 暂不做项一致）
- **下载原 .html**——归 §4.4 私有访问与管理 *(语义属"管理动作"，但 UI 上自然会出现在 Full Render 视图内的"更多"入口)*

### 4.4 私有访问与管理

**描述**：本节承载两类相关但语义不同的能力——

1. **私有访问**：兑现 brief 中"仅 alex 一人使用"的承诺，把 MindPrint 从公开 web 应用变成 alex 的私人空间。NFR-2 的源头。
2. **Entry 事后管理**：对已归档的 Entry 进行**编辑显示标题 / 下载原 .html / 永久删除**等动作。

Realizes：本节服务全部 UJ（UJ-1/2/3）的"长期可持续使用"基础——没有私有访问 alex 不敢放思维档案进去；没有管理动作 alex 无法清理误归档 / 修正难看的自动标题。

> **依赖关系**：FR-6（认证）是 FR-1 ~ FR-7 全部能力的**前置依赖**——未认证状态下任何能力都不可用（详见 §5 NFR-2 三层隔离）。

**功能性需求**：

#### FR-6：私有访问控制（认证能力）

仅 alex 可访问 MindPrint 的任何功能与数据。未认证请求一律被拒绝。

**测试性后果**：
- 任何未认证请求（无论访问哪个页面 URL 或 API 端点）一律返回明确的"未授权"响应，并引导至登录入口
- 认证成功后 alex 在合理时长内保持会话——[ASSUMPTION A6: 默认会话期 30 天 / "保持登录"]
- 认证机制（magic link / 单一密码 / passkey / 其他）由架构阶段决定——见 §5 NFR-2 与 `addendum.md` §2.3
- 同一时刻支持多设备同时登录（任意设备的浏览器都能访问，brief V1 硬约束）

**Out of Scope**：
- 多用户 / 用户注册流程 / 社交登录 / 邀请机制 *(brief 明示不做)*
- 双因素认证 / 设备管理面板 *(V1 alex 一人用，不必)*

#### FR-7：Entry 事后管理动作

alex 可对单一 Entry 做事后管理：**编辑显示标题**、**下载原 .html**、**永久删除**。所有管理动作的 UI 入口集中在 Full Render 视图（详情位置由 UX 阶段决定）。

**测试性后果**：

**编辑显示标题**：
- alex 可在 Full Render 视图触发对当前 Entry 的显示标题编辑
- 编辑后立即生效——时间线卡片与 Full Render 顶部 chrome 同步反映新标题
- 归档时间戳**不变**
- 长度限制 200 字符（与 FR-2 一致）

**下载原 .html**：
- alex 可从 Full Render 视图下载当前 Entry 的原始 .html 文件
- 文件名以**当前显示标题**为基础（含中文兼容；文件系统非法字符替换为下划线），扩展名 `.html`
- 下载内容**字节级别等同于**归档时上传的原 .html 文件——MindPrint 不做后处理 / 不修改
- 该能力同时承担"数据所有权"承诺的兜底——alex 任何时刻都能把单条 Entry 取回本地

**永久删除**：
- alex 可永久删除单一 Entry
- 删除前**必须二次确认**（确认弹层 / 模态，明确告知"删除后无法恢复"）
- 删除**不可撤销**——V1 不做垃圾桶 / 时间窗还原
- 删除后跳转回时间线；该 Entry 不再出现在任何视图
- 删除动作会**同时移除**原始 HTML 内容 + 元数据 + 缩略预览资源（若存在）

**Out of Scope**：
- 批量管理 / 多选 / 批量删除 *(V1 单条操作)*
- 软删除 / 回收站 / 时间窗恢复 *(V1 硬删除)*
- 全量导出 / 一键下载所有 Entry *(V1 不做；`[NOTE FOR PM]` 数据所有权诉求的"批量迁出"场景未来可能需要)*
- 编辑 Entry 的 HTML 内容（与 §4.3 FR-5 Out of Scope 第二条一致，归档即不可变快照）

## 5. Cross-Cutting NFRs *(Adapt-In · hobby 项目最小集合)*

> *跨所有 Features 的非功能性约束。每条 NFR 在 §4 中已被相关 FR 引用——本节是它们的**定义位置**，避免在多个 FR 中重复表达。*

### NFR-1：HTML 渲染沙箱化

**任何** Entry 的 HTML 内容渲染（卡片缩略预览见 §4.2、Full Render 见 §4.3）必须满足：

- **凭据隔离**：渲染上下文**无法访问** MindPrint 应用的——
  - 认证凭据（Cookie / Session Token / `localStorage` / `sessionStorage`）
  - 同源存储 / IndexedDB
  - 应用私有 API（即便能拼出 URL 也无法假冒 alex 身份调用）
- **行为隔离**：Entry HTML 内的 `<script>` 不能 ——
  - 修改宿主页面 DOM / `top.location` / `parent` 引用
  - 通过 `postMessage` 等通道获取 MindPrint 应用状态（除非显式建立白名单通道）
- **机制开放**：iframe `sandbox` 属性组合 / 独立 origin 子域名（如 `render.<domain>`）/ 严格 CSP 策略 / 上述组合等候选方案均可接受。**由架构阶段决定**——参见 `addendum.md` §2.1
- **被引用于**：§4.2 FR-4（缩略预览也算渲染）、§4.3 FR-5（Full Render）

### NFR-2：私有访问（仅 alex）

MindPrint 的**所有数据与界面**仅对认证后的 alex 可见。**承接 brief"可有最简私有认证"立场**——本节列出的三层隔离是面对 untrusted HTML 渲染（§4.2 缩略预览 + §4.3 Full Render）时不得不展开的**最小集合**，不是追求完整的私有访问控制系统。

**三层隔离**——

- **应用层**：所有页面 URL 在未认证状态下重定向至登录入口
- **API 层**：所有 API 端点（Entry 列表、单 Entry 内容、元数据、缩略预览资源、文件下载）在未认证状态下返回明确的"未授权"响应，**不**返回部分数据 / 不返回提示信息（例如返回 401 而非 404，避免泄露 Entry 是否存在）
- **资源层**：原始 .html 文件的存储位置**不应**可通过猜测 / 枚举 URL 直接访问——即使获取了直链也必须重新经过认证。这是为了防止"链接外泄即数据外泄"
- **机制开放**：认证机制（magic link / 单密码 / passkey / IP 白名单 + 共享密码等）由架构阶段决定，参见 `addendum.md` §2.3
- **被引用于**：§4.4 FR-6 的源头

### NFR-3：基本可靠性（hobby 最小集合）

> *本节为 hobby 项目**软目标**，不是硬性 SLA。工程师写代码时按此为指南；M3 retro 阶段视实际使用稳定性决定是否升级。*

- **错误隔离**：单条 Entry 损坏 / 渲染失败 / 缩略预览生成失败**不应阻塞**时间线整体——其他 Entry 仍可正常浏览。Full Render 失败时显示错误信息但 alex 仍可通过"返回时间线"导航离开。
- **数据持久**：归档完成的 Entry **除非 alex 主动通过 FR-7 删除，否则不得丢失**（**hard requirement**——本节其他条款为软目标，仅此条为硬约束）。这是 brief §M1 业务里程碑（"alex 自己能日常使用、**不会再丢东西**"）的工程对应。
- **浏览器覆盖**：支持当前主流桌面浏览器（Chrome / Safari / Firefox 各最新稳定版）+ 主流移动浏览器（iOS Safari / Android Chrome 各最新稳定版）。**不支持** IE / 旧版 Edge / 桌面 PC 的小众浏览器。
- **响应感（软目标）**：[ASSUMPTION A7] 时间线主屏首屏渲染 < 2 秒（50 条目以内）；Full Render 从单击卡片到 HTML 可见 < 1 秒。未达成**不阻塞上线**，但是 M3 retro 关注点。

## 6. Non-Goals（显式排除）

### 6.1 产品方向上不做（永久边界）

- **多用户 / 协作 / 团队**——MindPrint 是 alex 的私人档案库，多用户违反产品本质

- **AI 自动生成 HTML / 内置编辑器**——MindPrint 是 .html 的**容器**，不是生产工具；HTML 由 alex 在外部（Cursor / Claude 等）产出
- **与 Notion / GitHub Pages / tiiny.host 等替代品的功能性 / 体验性竞争对照**——承接 brief §差异化坦白态度：本产品不与替代品做竞争性比较，它存在的依据仅是 alex 的数据所有权偏好 + 自研历练目标

### 6.2 V1 暂不做（未来视使用情况评估）

> *与 brief §V1 暂不做 + §4 各 FR Out of Scope 一致。每条标注关联 OQ（如有），M3 retro 时按 OQ 触发条件分诊。下游 UX / 架构 / Epic 阶段**不应**为这些功能预留任何脚手架。*

- 移动端原生 App / PWA
- 自动从 ~/Downloads 同步
- 标签 / 搜索 / 过滤
- 版本对比 / 历史快照
- 批量管理（上传 / 删除 / 编辑）
- 全量导出 / 一键迁出（**关联 OQ-7** · `[NOTE FOR PM]` 数据所有权诉求的关键缺口）。**与 brief §差异化"数据所有权"立场存在张力**——V1 通过 FR-7 单条下载**部分承接**，全量导出未做。M3 retro 时若 alex 决定换平台 / 部署目标变更，缺少全量导出会造成迁出门槛
- 内容去重 / 重复检测（**关联 OQ-3**）
- Entry HTML 内容事后编辑（归档即不可变快照）
- 沉浸全屏模式（隐藏 MindPrint chrome，**关联 OQ-6**）
- 双因素认证 / 设备管理面板
- 列表视图切换（V1 仅卡片网格）
- 时间线行内操作（hover 删除等，所有管理动作集中在 Full Render）

## 8. 成功指标

> *每条 SM 引用其验证的 FR；Counter-metrics 与 Primary 一一制衡——下游架构 / dev / 未来 PM 视角的 "不该被优化的方向"。SM-1 可机器测量，SM-2/SM-3/SM-4/SM-5/SM-6 为 alex 自我评估（hobby 项目可接受的可信度）。*

### 8.1 Primary（产品层 — 承接 brief）

- **SM-1**：**上线后 3 个月内 alex 实际打开回看次数 ≥ 8 次**（约每月 2-3 次，与"经常翻看"匹配）。
  - 计量方法：服务端记录 alex 进入时间线 / Full Render 的次数，30 分钟内重复访问算同一次。
  - 验证 **FR-4, FR-5**（时间线浏览 + 完整渲染的实际使用）

- **SM-2**：**上线后 0 起新增"找不到/丢失"事件**。
  - 计量方法：alex 自我报告（事件级，主观但精确——一旦发生记得清楚）
  - 验证 **FR-1, FR-2, FR-7**（归档完整、元数据可靠、删除路径明确不误删）

- **SM-3**：**上线后 80% 以上新产出的 .html 进入 MindPrint**，不再仅留在 ~/Downloads。
  - 计量方法：alex 自我估算（季度回顾时对照 ~/Downloads 的 .html 数量与 MindPrint 内同期归档数量）
  - 验证 **FR-1**（归档的低摩擦设计）

### 8.2 Secondary（元层 — alex 的练手目标）

- **SM-4**：**完整跑通一次"借助 AI 的" BMAD 标准流程**——brief → PRD → UX → 架构 → epics/stories → dev → 上线。**承接 brief §差异化**"借助 AI 完整跑一遍"——"借助 AI"是过程性强调，不仅看产物存在与否，也评估 alex 借助 AI 完成度的可复制性。
  - 计量方法：BMAD 各阶段产物在 `_bmad-output/` 下完整存在且 status 为 final + alex 自评"借助 AI 完成度"作为辅助维度
- **SM-5**：**完成一次完整的"前端 + 后端 + 数据库 + 云部署"全栈实战**。
  - 计量方法：代码仓库的目录结构与 MindPrint 部署后的可达性即证明
- **SM-6**：**上线后 3 个月内不因架构问题被迫重构**。
  - 计量方法：alex 自我评估，季度 retro

### 8.3 Counter-metrics（反向指标——下游**不该**优化的方向）

- **SM-C1**：**不优化"归档数量"** —— alex 不应为了刷 SM-3 而归档无意义的 HTML。**归档率高 ≠ 归档质量高**。制衡 SM-3。
- **SM-C2**：**不优化"打开频次"** —— MindPrint **不应**通过推送 / 邮件提醒 / 红点 / 通知等机制刺激 alex 打开应用。SM-1 必须是**自然产生的回看行为**。制衡 SM-1。
- **SM-C3**：**不为低使用率扩 V1 边界** —— 若 SM-1 / SM-3 不达预期，**首选反思"是不是不需要"而非"加更多功能"**。这与 brief §M3 里程碑明确呼应（"决定是否继续迭代，还是保持简单即可"）。制衡所有 Primary SMs。

### 8.4 业务里程碑承接（brief §业务里程碑）

> *M1/M2/M3 是 brief 明确强调的"业务里程碑"——产品**何时该判断"是否继续做"**的决策节点。*

- **M1 · V1 上线** — alex 自己能日常使用、不会再丢东西
  - 验证标准：**SM-2**（0 起新增"找不到/丢失"事件）+ **SM-3**（80% 新产出归档进入）共同达成
- **M2 · 累计 50+ 条目** — 从时间线能明显感受到自己思维演进
  - 验证标准：在 50+ Entry 规模下，alex 自评是否能从 **FR-4 时间线** + **月份分隔条** + **HTML 缩略预览** 中**直观感受到"思维演进"**——这是 §1 thesis 兑现的关键测试节点
- **M3 · 三个月稳定运行** — 决定是否继续迭代（加搜索/标签/同步），还是它已经够用、保持简单即可
  - 验证标准：**SM-6**（不被迫重构）+ **SM-C3**（不为低使用率扩 V1 边界） —— retro 时按 §9 OQs 触发条件分诊，决定哪几条进 v2 / 哪几条永久搁置
