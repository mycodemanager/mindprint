## 2026-05-28 · §10 Cross-Cutting NFRs

- **3 条 NFR 写完**：
  - **NFR-1 HTML 渲染沙箱化**——凭据隔离 + 行为隔离 + 机制开放。**双向隔离**——既禁止 Entry HTML 越权读 MindPrint 数据，也禁止其修改宿主 DOM / `top.location` 等
  - **NFR-2 私有访问三层**——应用层 / API 层 / 资源层。**关键细节**：401 而非 404（不泄露 Entry 是否存在）；直链不应可访问（防止"链接外泄即数据外泄"）。这两条比 brief 默认的"私有"语义都更紧
  - **NFR-3 hobby 最小可靠性软目标**——错误隔离 / 数据持久（接 brief §M1）/ 浏览器覆盖 / 响应感软目标
- **没做的事**：
  - 没写 SLA / RTO / RPO——hobby 项目过度承诺，反而是 PRD 走偏的信号
  - 没写"全量数据导出"为 NFR——FR-7 单条下载已支持，全量推迟 v2 已在 §5.2
- **A7 新增**：响应感软目标（首屏 < 2s, Full Render < 1s）。明确标"未达成不阻塞上线"——以免下游 dev 把它当硬指标卡住进度
- **NFR 数**：3 条
- **新增 Assumptions**：A7

## 2026-05-28 · §4.4 私有访问与管理

- **结构选择**：本节合并两类相关能力——私有访问（认证）+ Entry 事后管理。理由：两者都服务"长期可持续使用"的基础，且事后管理动作的 UI 自然在 Full Render 内集中
- **FR 拆分**：FR-6（认证）+ FR-7（管理动作合并）共 2 条
- **关键决策点**：
  - **FR-6 单一职责：能力 = "仅 alex 可访问"**，机制（magic link / 单密码 / passkey）留架构。多设备同时登录支持
  - **会话默认 30 天（A6）**——hobby 个人用，每次重输密码会破坏体验
  - **FR-7 合并 3 个管理动作**（编辑标题 / 下载 / 删除）一条 FR——它们都是"alex 对一个 Entry 的事后操作"，分 3 条 FR 反而散
  - **删除：二次确认 + 硬删除**——V1 不做垃圾桶。alex 是工程师能管好自己，简洁优先
  - **下载：原字节流，不后处理**——同时是数据所有权承诺的兜底
  - **下载文件名规则**：基于当前显示标题（中文兼容，非法字符替换下划线），不是原始文件名
  - **管理动作 UI 集中在 Full Render**——逻辑统一，避免时间线卡片堆按钮造成视觉噪音 / 误触
- **未做的事 / 留 v2 口子**：
  - 批量管理（删除/编辑）V1 不做
  - 全量导出 V1 不做，[NOTE FOR PM] 留口子（数据所有权诉求的批量迁出场景）
  - 双因素 / 设备管理 / 软删除均 V1 不做
- **FR 数**：2 条（FR-6 + FR-7）
- **新增 Assumptions**：A6

## 2026-05-28 · §4.3 完整渲染（Full Render）

- **结构选择**：单条 FR-5 涵盖渲染体验全部。NFR-1 沙箱化在 §4.3 引用、定义放 §10 cross-cutting（避免重复）
- **FR 编号修正**：原计划 §4.3 是 FR-6，但 §4.2 实际只有 1 条 FR-4（不是 FR-4+FR-5），所以 §4.3 自然成 FR-5
- **关键决策点**：
  - **全屏式渲染区域**——最大化"原貌呈现"体感，而不是嵌入式小窗口
  - **"原貌等同性"明确写为可测后果**——视觉上等同于双击 .html 打开浏览器；仅沙箱化副作用为例外（具体例外类型也写明，避免后端实现争议）
  - **"上一条 / 下一条" 导航 V1 必须**——UJ-3 顺序回看的连续性体感不可少。每次"返回时间线再点下一条"的断点感会显著降低 UJ-3 完成度
  - **加载失败不污染归档状态**——与 FR-3 一致，Entry 入库与渲染体验解耦
  - **响应式**——brief V1 硬约束（任意设备浏览器可用）的直接承接
  - **沙箱化机制留架构**——iframe sandbox / 独立子域名 / CSP 等候选已在 addendum §2.1
- **明确推到其他节的**：
  - "下载原 .html" → §4.4 私有访问与管理（语义上属管理动作）
  - "沉浸全屏模式" → Out of Scope，[NOTE FOR PM] 留 v2 口子
  - "Entry HTML 内容编辑" → Out of Scope（一旦归档即不可变快照）
- **FR 数**：1 条（FR-5）
- **新增 Assumptions**：无

## 2026-05-28 · §4.1 归档（Archive）

- **结构选择**：把"归档"作为**单一连贯动作**呈现（上传 → 元数据捕获与确认 → 进入档案库），而非拆成 3 个独立 feature。理由：UJ-2 的视角下这是一段无缝体验，FR 数控制在 3 条（FR-1/2/3）。
- **关键决策点**：
  - **拖拽 + 点击选择都支持**——浏览器标准范式，跨设备零教育成本
  - **V1 仅单文件**——和 brief"HTML 文件上传（单文件）"一致
  - **大小上限 10MB**（A2，标记 [ASSUMPTION]）——AI 生成 HTML 偶含 base64 图片，5MB 偏紧，10MB 留余地
  - **元数据：归档时间戳不可编辑**——保证时间线真实性。**显示标题可编辑**——alex 是控制狂工程师，自动抽取的 `<title>` 经常不令人满意，必须给编辑口子
  - **V1 不做去重**——hobby 项目复杂度优先压低；[NOTE FOR PM] 留口子
  - **归档成功后直接进入 Full Render**——立即给 alex"档案库正确接住"的确认信号
  - **渲染失败 ≠ 归档失败**——Entry 入库与渲染体验解耦，避免坏 HTML 阻塞归档动作
- **FR 数**：3 条（FR-1 / FR-2 / FR-3）
- **新增 Assumptions**：A2、A3
