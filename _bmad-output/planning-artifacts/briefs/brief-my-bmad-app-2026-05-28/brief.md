# 产品简报：MindPrint *（产品名待定）*

> **一句话**：MindPrint 是 alex 自托管的个人 HTML 知识资产库——把日常借助 AI 产出的 .html 内容集中存放、按时间线渲染浏览，用于回看自己思维逻辑的演进。

## 概要

alex 是前端工程师，正借助 AI 向全栈转型。日常用 AI 产出大量 HTML 形式的思维产物（UI 规范、调研报告、原型、思考片段），这些文件目前散落在 macOS 的 ~/Downloads 和各工作项目目录里，已发生过"想回看却找不到"的实际损失。MindPrint 把这些散落资产收拢为一个可时间线浏览、可直接渲染查看的私人 web 应用，让 alex 已经在做且确认能"提升思维逻辑"的"回看自己旧产物"这个行为变得可持续。

这同时也是 alex 借助 AI 完成前端→全栈能力闭环的第一个真实项目——既是工具，也是历练。

## 用户

唯一用户：**alex**。

- 前端工程师，正借助 AI 向全栈转型
- 日常借助 Claude / Cursor 等工具产出 .html 形式的思维产物
- 已经有定期回看旧产物的习惯，且明确感到这件事"对思维逻辑是一种提升"
- 偏好自己掌控数据，不愿把个人知识资产托付给第三方 SaaS

## 问题

1. **散落** — .html 文件被随手存在 ~/Downloads、各工作项目目录，没有统一位置
2. **遗忘 + 实际丢失** — 时间一长记不起来"曾经做过什么"，且**已发生**找不到的事实
3. **.html 的渲染门槛** — 不同于 .md 的纯文本浏览，HTML 必须经浏览器渲染才能体现原貌；Finder 双击预览体验破碎，不支持"画廊式翻看"
4. **现成方案不匹配诉求** — GitHub Pages/Gist 数据在第三方，Notion/飞书嵌 HTML 体验差，tiiny.host 等是为"临时分享"设计——没有专为"长期个人思维档案 + 时间线回看"的语义

## 方案

一个**自托管 / 部署在云上**的个人 web 应用：

- **入口**：上传 .html 文件，自动记录时间戳与元数据
- **浏览**：时间线视图，按时间倒序展示所有产物
- **渲染**：点击任一条目，直接在浏览器中**完整渲染** HTML 原貌
- **归属**：所有内容存储在 alex 自己掌控的位置（具体技术方案留给架构阶段）

## 差异化

诚实地说：**这不是为商业差异化设计的产品**——市场上已有大量替代品（GitHub Pages、Notion、tiiny.host 等），任何一个都能勉强满足表层需求。

它的存在仅基于两个主观但真实的诉求：

1. **数据所有权** — alex 的个人知识资产应在 alex 自己掌控的存储里，不依赖任何特定第三方
2. **自研历练** — 这是 alex 从前端转全栈的第一个真实项目，要借助 AI 完整跑一遍 BMAD 流程 + 前后端 + 部署上线的全栈实战

这两个诉求决定了：即使现成方案"够用"，仍要做。

## 成功标准

### 产品层
- 上线后 **3 个月内**，alex 实际打开回看次数 ≥ **8 次**（约每月 2~3 次，与"经常翻看"匹配）
- 上线后 **0 起**新增"找不到/丢失"事件
- 上线后 **80% 以上**新产出的 .html 进入 MindPrint，不再仅留在 ~/Downloads

### 元层（练手）
- 完整跑通一次 BMAD 标准流程：brief → PRD → UX → 架构 → epics/stories → dev → 上线
- 完成一次完整的前端 + 后端 + 数据库 + 云部署 全栈实战
- 上线后 3 个月内不因架构问题被迫重构

## 范围

### V1 必须有
- HTML 文件上传（单文件）
- 时间线列表浏览（时间倒序）
- 点击进入完整渲染查看
- 部署到云上，alex 在任意设备的浏览器都能访问

### V1 暂不做
- 移动端原生 / PWA
- 对外分享外链
- 多用户 / 协作
- 标签 / 搜索
- 版本对比 / 历史
- 自动从 Downloads 同步

### V1 硬约束
- 无自有服务器：基于通用云服务（Vercel / Netlify / Cloudflare 等）+ 托管数据库（Supabase / Neon / Turso 等）部署
- 仅 alex 一人使用：可有最简私有认证，无注册流程、无社交

## 愿景

- **2 年视角**：alex 已完成前→全栈的能力建设；MindPrint 继续作为他日常的产出归档地
- **5 年视角**：MindPrint 沉淀了 alex 多年的 HTML 思维产物，从中能直观回看自己每一阶段的思维变化——这本身就是工具最大的价值，也是这个项目最初设立的初心

## 业务里程碑

> 注：按范式文档要求，里程碑是**业务里程碑**而非功能交付里程碑。

- **M1 · V1 上线** — alex 自己能日常使用、不会再丢东西
- **M2 · 累计 50+ 条目** — 从时间线能明显感受到自己思维演进
- **M3 · 三个月稳定运行** — 决定是否继续迭代（加搜索/标签/同步），还是它已经够用、保持简单即可
